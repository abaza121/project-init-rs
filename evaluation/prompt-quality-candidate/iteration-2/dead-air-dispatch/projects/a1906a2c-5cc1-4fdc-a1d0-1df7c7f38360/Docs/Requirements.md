# Dead Air Dispatch Product Register

## Requirements
REQ-001: The playable shall implement the requested game form, platform, premise, and player role; exact brief wording: “I want to make a strange 2D score-attack game for PC in which the player operates an emergency radio during a supernatural storm.”
REQ-002: The playable shall make tuning the prerequisite for seeing the arena; exact brief wording: “The arena is invisible until the player turns a tuning dial with the mouse wheel”.
REQ-003: The playable shall make frequency selection reveal the specified categories; exact brief wording: “different frequencies reveal different hazards, stranded callers, and safe routes”.
REQ-004: The playable shall make tuning alter entity audibility and approach behaviour; exact brief wording: “tuning also changes which entities can hear and approach the station.”
REQ-005: The playable shall implement the complete repeating interaction sequence; exact brief wording: “The repeating loop is to scan, identify a caller's frequency, hold the signal long enough to guide them home, then retune before hostile interference reaches the antenna.”
REQ-006: The playable shall use five minutes as the run-duration target while leaving the permitted deviation unresolved; exact brief wording: “A run should last about five minutes”.
REQ-007: The playable shall calculate score from all three named components without assigning unresolved relative weights; exact brief wording: “score the player for rescues, signal accuracy, and risky time spent near dangerous bands.”
REQ-008: The first playable shall be achievable within the permitted low-fidelity presentation and room scope; exact brief wording: “The first playable can use abstract waveforms, silhouettes, static, and layered sound in a single room.”
REQ-009: The first playable shall expose the named hidden-information risk for later evaluation without inventing a success cutoff; exact brief wording: “The central risk is making hidden information feel intriguing rather than unfair”.
REQ-010: The package shall preserve accessibility support as an unresolved stakeholder choice and shall not promote candidate features to settled scope; exact brief wording: “I have not decided how to support deaf or hard-of-hearing players.”

## Acceptance Criteria
AC-001: Inspection of a PC build passes if it presents a 2D play view, an emergency-radio control role, a supernatural-storm setting, a score display, and a runnable score-attack session; otherwise it fails supports REQ-001 because the PC build observation tests the 2D score-attack emergency-radio storm game form.
AC-002: A fresh-session input test passes if the arena supplies no actionable arena view before any tuning input and the first mouse-wheel tuning input reveals an actionable tuned view; otherwise it fails supports REQ-002 because the mouse-wheel tuning observation tests the invisible arena prerequisite.
AC-003: A frequency-fixture test passes if at least one hazard, one stranded caller, and one safe route are each absent outside their configured frequency reveal and visible at their configured frequency reveal; otherwise it fails supports REQ-003 because the frequency-fixture observation tests hazards, stranded callers, and safe routes.
AC-004: A paired-frequency simulation passes if the same entity is unable to hear or approach the station on one configured frequency and can hear and reduce its station distance on another configured frequency; otherwise it fails supports REQ-004 because the entity simulation tests tuning-dependent hearing and approach.
AC-005: A scripted caller scenario passes if the event log records scan, caller-frequency identification, uninterrupted signal hold through the configured rescue duration, caller-home completion, retune, and hostile-interference avoidance before antenna contact in that order; otherwise it fails supports REQ-005 because the ordered event log tests the complete scan-identify-hold-guide-retune loop.
AC-006: Configuration inspection passes if the nominal run target is exactly 300 seconds and no undocumented tolerance is used as an acceptance boundary; otherwise it fails supports REQ-006 because the 300-second target observation tests five minutes while preserving the unresolved permitted deviation.
AC-007: A deterministic scoring fixture passes if changing only rescues changes the rescue component, changing only signal accuracy changes the accuracy component, and changing only dangerous-band time changes the risk component, with each component included in the displayed total and no undocumented relative weight; otherwise it fails supports REQ-007 because the independent component observations test rescues, signal accuracy, and risky dangerous-band time.
AC-008: First-playable scope inspection passes if the complete REQ-005 loop is demonstrable in one room using abstract waveforms, silhouettes, static, and layered sound as sufficient production materials, without dependency on additional rooms or representational final art; otherwise it fails supports REQ-008 because the one-room low-fidelity inspection tests the permitted first-playable presentation scope.
AC-009: Package inspection passes if the hidden-information phrase is recorded as the central risk, OQ-003 remains unresolved, and no numeric intriguing-versus-unfair cutoff is asserted; otherwise it fails supports REQ-009 because the risk and unresolved-cutoff observations test honest exposure of hidden-information fairness.
AC-010: Package inspection passes if OQ-001 remains unresolved and no caption, visual-equivalence, default, directional-indicator, non-colour, or audio-muted-completion feature is labeled settled first-playable scope; otherwise it fails supports REQ-010 because the unresolved accessibility observations preserve the undecided support for deaf or hard-of-hearing players.
