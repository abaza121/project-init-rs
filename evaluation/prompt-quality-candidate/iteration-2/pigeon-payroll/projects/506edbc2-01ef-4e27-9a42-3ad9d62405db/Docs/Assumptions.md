# Project Boundaries

## Assumptions

ASM-001: ASSUMPTION: Allowing a shift to continue while failure reduces wages is a non-authoritative prototype hypothesis inferred from the playful-tone constraint and wage-deduction mechanic; it is not the selected failure rule.
ASM-002: ASSUMPTION: A platform-neutral gameplay core with replaceable device adapters is a non-authoritative implementation inference intended to limit rework while the primary mobile platform remains unselected.
ASM-003: ASSUMPTION: Score rewards, breadcrumb cleanup costs, and combo multipliers should be runtime-configurable tuning parameters; no numeric value or relative weight is authorized.
ASM-004: ASSUMPTION: The first prototype can run locally without accounts, analytics, advertising, purchases, cloud persistence, or a network backend because none is requested in the brief; production data handling remains unassessed.
ASM-005: ASSUMPTION: The proposed palette, typography, character shapes, and asset-generation prompt are provisional creative directions because the intended audience remains unselected.

## Constraints

CON-001: Every breadcrumb must also attract more pigeons; exact supplied constraint wording: “every breadcrumb also attracts more pigeons”.
CON-002: The cleanup bill must be deducted from the final score; exact supplied constraint wording: “adds to a cleanup bill deducted from the final score”.
CON-003: Presentation must remain playful rather than stressful; exact supplied constraint wording: “playful rather than stressful”.
CON-004: The first prototype is limited to one cafe screen; exact supplied constraint wording: “A first prototype only needs one cafe screen”.
CON-005: The first prototype is limited to three customer tables; exact supplied constraint wording: “three customer tables”.
CON-006: The first prototype is limited to a small pigeon behaviour set; exact supplied constraint wording: “a small set of pigeon behaviours”.
CON-007: The brief fixes a rough shift duration of 60 to 90 seconds.
CON-008: The intended audience has not been selected by a stakeholder.
CON-009: The failure rule has not been selected by a stakeholder.
CON-010: The primary mobile platform, engine, minimum device versions, and performance budgets are not supplied.
CON-011: The prototype learning goal, success threshold, exact pigeon behaviour membership, and numeric scoring economy are not supplied.

## Handling

Assumptions may guide replaceable prototype seams but may not close an open choice. Constraints bind scope unless a stakeholder explicitly changes them.
