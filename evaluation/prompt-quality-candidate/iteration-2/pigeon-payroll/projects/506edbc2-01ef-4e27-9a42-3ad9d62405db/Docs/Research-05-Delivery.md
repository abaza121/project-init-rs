# Prototype Delivery Guidance

## Current Findings

EVD-006: The HEART framework describes mapping product goals to user-centered metrics used to measure progress and inform product decisions. [Measuring the User Experience on a Large Scale — Google Research](https://research.google/pubs/measuring-the-user-experience-on-a-large-scale-user-centered-metrics-for-web-applications/) supports DEC-003 because goal-to-metric mapping requires a Pigeon Payroll learning goal before measurable prototype pass/fail criteria.
EVD-007: GOV.UK guidance says teams should define learning objectives, agree the questions they need to answer, and turn unfounded assumptions and opinions into questions. [Plan user research for your service — GOV.UK Service Manual](https://www.gov.uk/service-manual/user-research/plan-user-research-for-your-service) supports DEC-003 because learning objectives must precede Pigeon Payroll prototype success measures.
EVD-008: The UK Government Service Standard says teams should define what success looks like and select metrics indicating how well the intended problem is being solved, used with user inquiry. [Define what success looks like — GOV.UK Service Manual](https://www.gov.uk/service-manual/service-standard/point-10-define-success-publish-performance-data) supports DEC-003 because intended outcomes must precede Pigeon Payroll success thresholds.
EVD-009: GOV.UK alpha guidance advises identifying the riskiest assumptions and building only enough complexity to test them, while noting that the riskiest assumptions depend on the product. [How the alpha phase works — GOV.UK Service Manual](https://www.gov.uk/service-manual/agile-delivery/how-the-alpha-phase-works) supports DEC-004 because a Pigeon Payroll gameplay risk must precede selection of the minimum pigeon behaviour set.
EVD-010: UK Government guidance says the appropriate prototyping approach depends on the questions to answer, project stage, and available resources. [Delivery: prototyping and improving ideas — GOV.UK Open Policy Making Toolkit](https://www.gov.uk/guidance/open-policy-making-toolkit/4-delivery-prototyping-and-improving-ideas) supports DEC-004 because a Pigeon Payroll prototype question must precede exact pigeon behaviour selection.
EVD-011: Research on automatic game parameter tuning describes evaluating candidate parameter settings against a predefined design goal. [Automatic Playtesting for Game Parameter Tuning via Active Learning — arXiv](https://arxiv.org/abs/1908.01417) supports DEC-005 because a Pigeon Payroll scoring design goal must precede numeric score and cleanup-bill tuning.
EVD-012: Peer-reviewed game analysis reports that player skill, game variants, and learning affect difficulty and observed score distributions. [Comparing Player Skill, Game Variants, and Learning Rates Using Survival Analysis — AIIDE](https://ojs.aaai.org/index.php/AIIDE/article/view/12846) supports DEC-005 because Pigeon Payroll score distributions require empirical evaluation rather than an unsupported formula.
