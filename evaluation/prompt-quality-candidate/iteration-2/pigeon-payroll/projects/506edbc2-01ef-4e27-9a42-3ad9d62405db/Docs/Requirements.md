## Acceptance Criteria

AC-001: Inspection finds an explicit unresolved audience state naming children, casual adults, and both, with no selected audience; pass if present and fail otherwise supports REQ-001 because the intended audience must remain unresolved among those three audience options.
AC-002: Inspection finds no implemented terminal failure rule and finds the end-run versus reduce-wages choice exposed as pending; pass if both observations hold and fail otherwise supports REQ-002 because the failure rule must remain unresolved between ending a run and reducing wages.
AC-003: Inspection finds no prototype go/no-go threshold and finds fields for a prioritized learning goal and acceptable success threshold; pass if both observations hold and fail otherwise supports REQ-003 because measurable prototype pass/fail criteria depend on those stakeholder inputs.
AC-004: Inspection finds the exact pigeon behaviour list uncommitted and gated by a prioritized gameplay question or riskiest assumption; pass if both observations hold and fail otherwise supports REQ-004 because exact prototype pigeon behaviours must remain unresolved pending that priority.
AC-005: Inspection finds score rewards, cleanup costs, and relative weights represented as unset configurable values rather than approved constants; pass if all are unset and fail otherwise supports REQ-005 because exact scoring and cleanup-bill calculations remain stakeholder-owned.
AC-006: Inspection finds no primary mobile platform selection and records all five missing inputs: build hardware, tester devices, market, distribution goal, and budget; pass if all observations hold and fail otherwise supports REQ-006 because primary mobile platform selection depends on those inputs.
AC-007: A prototype build runs through touch input in a portrait mobile viewport, uses an arcade shift timer, and makes a pigeon theft trigger both squash-and-stretch motion and a slapstick sound; pass if all four observations occur and fail otherwise supports REQ-007 because the product subject is a comedic mobile arcade game.
AC-008: A playthrough identifies the player avatar as a cafe worker and provides an observable objective state for keeping pigeons away from outdoor customers; pass if both are observed and fail otherwise supports REQ-008 because the cafe worker’s objective concerns pigeons and outdoor customers.
AC-009: With all controls except touch disabled, one finger can swipe once to throw a breadcrumb and the thrown breadcrumb changes flock movement; pass if both effects occur and fail otherwise supports REQ-009 because one-finger swipes must throw breadcrumbs and herd the flock.
AC-010: For each breadcrumb in a ten-throw instrumented test, pigeon attraction count or attraction strength increases above its pre-throw value; pass only if all ten increase and fail otherwise supports REQ-010 because every thrown breadcrumb must attract more pigeons.
AC-011: For each breadcrumb in a ten-throw instrumented test, cleanup bill increases, and the result screen computes final score as gross score minus cleanup bill; pass only if all eleven observations hold and fail otherwise supports REQ-011 because every breadcrumb adds a cleanup bill deducted from final score.
AC-012: Three uninterrupted instrumented shifts each end at an elapsed duration from 60.0 through 90.0 seconds inclusive; pass only if all three durations are in range and fail otherwise supports REQ-012 because each completed shift must last 60 to 90 seconds.
AC-013: Instrumentation shows the configured chaos intensity in the final shift third is greater than in the first shift third; pass if the comparison is strictly greater and fail otherwise supports REQ-013 because each shift must become more chaotic over elapsed time.
AC-014: During a deterministic full-shift test, at least one customer leaves one table and occupies a different table; pass if the completed relocation occurs and fail otherwise supports REQ-014 because customers must move between tables during a shift.
AC-015: During a deterministic full-shift test beginning with no pastry present, at least one pastry entity becomes visible and interactable; pass if both properties are observed and fail otherwise supports REQ-015 because pastries must appear during a shift.
AC-016: A deterministic food-steal sequence by impatient pigeons increments a visible combo counter above one; pass if the counter exceeds one and fail otherwise supports REQ-016 because impatient pigeons must form combos by stealing food.
AC-017: A content inspection finds zero horror cues, punitive alarm loops, or hostile player-directed text, and a playtest prompt records the intended descriptor “playful” rather than “stressful”; pass if all observations hold and fail otherwise supports REQ-017 because presentation must be playful rather than stressful.
AC-018: In a silhouette-only identification check at the reference portrait resolution, five observers each label the cafe worker, customer, and pigeon correctly on every trial, and in a gameplay-scale expression check the same observers identify each displayed expression correctly on at least 90% of trials; pass if both thresholds are met and fail otherwise supports REQ-018 because bold readable character silhouettes and expressions must distinguish the cast.
AC-019: Logged events confirm distinct slapstick sound effects trigger for a breadcrumb throw, a pigeon food theft, and a combo; pass if all three triggers emit audio and fail otherwise supports REQ-019 because gameplay actions and mishaps require slapstick sound effects.
AC-020: On a test device, gameplay renders upright in portrait at both supported portrait orientations and never switches to landscape during a complete shift; pass if all observations hold and fail otherwise supports REQ-020 because gameplay must operate in portrait mode.
AC-021: Scene enumeration in the first prototype finds exactly one playable cafe screen; pass if the count equals one and fail otherwise supports REQ-021 because the first prototype scope is one cafe gameplay screen.
AC-022: Runtime entity enumeration on the cafe screen finds exactly three customer-table entities; pass if the count equals three and fail otherwise supports REQ-022 because the first prototype cafe screen scope is three customer tables.
AC-023: Behaviour enumeration finds a finite pigeon behaviour collection, while an approval check confirms its members were selected only after OQ-004 was resolved; pass if both observations hold and fail otherwise supports REQ-023 because the prototype needs a small pigeon behaviour set whose exact membership remains unresolved.
AC-024: The launch view and result view each display the exact text “Pigeon Payroll”; pass if both exact-string inspections succeed and fail otherwise supports REQ-024 because the project and prototype identity is Pigeon Payroll.

## Interpretation

“Must” is normative. The first six REQ records deliberately require unresolved states; they do not authorize the provisional options described elsewhere. The acceptance checks define feature conformance, not prototype market success; the latter remains OQ-003.
