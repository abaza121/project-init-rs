# Half-Mech Heroes — Project Initiation Package

This directory contains the initiation baseline for the first playable prototype. It is a documentation package, not an implemented game. Its central rule is that stakeholder wording, generated requirements, inferred assumptions, unresolved questions, research evidence, and decisions remain visibly distinct.

## Start here

1. [Requirements.md](Requirements.md) — canonical source-clause ledger, generated requirement register, objective acceptance criteria, and exact verification references.
2. [OpenQuestions.md](OpenQuestions.md) — canonical unresolved-choice register.

4. [Traceability.md](Traceability.md) — canonical consequential-decision register and exact semantic trace edges.

## Current authority state

- Accepted stakeholder scope is represented by SRC-to-REQ traces and accepted `DEC-*` records.
- Provisional numeric gates are high-impact assumptions and cannot close their related open questions.
- Platform, technology, remapping, solo play, difficulty scaling, exact target age, hazard identities, civilian identity, city-block boundary, experience thresholds, and explicit exclusions remain unresolved.
- Imported answers beginning with `FAIL` are preserved as evidence of non-resolution; they are not treated as chosen product requirements.

## Change discipline

When a stakeholder answers an open question, update the matching `OQ-*`, add or revise one single-subject `DEC-*` record with provenance and rationale, update affected requirements and assumptions, add explicit trace edges, and rerun the checks described in ValidationReport.md. Research may constrain that decision but may not be cited as stakeholder authority.
