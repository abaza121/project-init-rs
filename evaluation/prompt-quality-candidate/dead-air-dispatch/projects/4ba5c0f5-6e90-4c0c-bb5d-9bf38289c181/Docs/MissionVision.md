# Mission and Vision

Status: proposed, non-authoritative.  
Decision: `D-004`.  
Source basis: `SRC-002`, `SRC-003`, `SRC-004`, `SRC-005`, and `SRC-007` in [Requirements.md](Requirements.md).

## Proposed mission

Create a compact 2D score-attack experience in which tuning an emergency radio turns uncertainty into moment-to-moment rescue decisions, while every hidden danger is learnable enough to feel tense rather than arbitrary.

This is an internal synthesis, not an additional requirement. The canonical mechanics and acceptance conditions remain in [Requirements.md](Requirements.md).

## Proposed vision

Dead Air Dispatch should be recognizable as a supernatural radio game where perception is an action: the player chooses what to reveal, what to attract, and how long to risk holding a signal. A successful experience would make a short run readable enough to support deliberate improvement while preserving unease.

“Readable enough,” “deliberate improvement,” and “successful” are aspirations, not approved thresholds. `OQ-002` and `OQ-004` must be answered before this vision can be evaluated as an acceptance claim.

## Proposed design principles

1. **Tuning changes the situation.** Scanning is not a passive overlay; it changes revelation and threat response. This principle is a summary of `DAD-REQ-005`, `DAD-REQ-006`, and `DAD-REQ-007`.
2. **Rescue requires commitment.** Identification and signal hold create a window of exposure. This principle summarizes `DAD-REQ-009`, `DAD-REQ-010`, and `DAD-REQ-011`.
3. **Risk should be interpretable.** The player should have evidence from which to learn, but no test population, measure, or threshold is authorized; see `DAD-REQ-015`.
4. **Score should reveal priorities.** All three authorized score inputs remain visible, while their weights remain open under `D-009`.
5. **Access choices require explicit scope.** Evidence-backed options are candidates only; see `D-007`, `D-015`, and `OQ-001`.

## Success boundary

Mission acceptance is not declared in this package. It depends on approved audience, fairness evaluation, accessibility scope, run-duration bounds, score weights, and first-playable definition in [OpenQuestions.md](OpenQuestions.md).
